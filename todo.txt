# SynAccel Sentinel Roadmap

## Implemented

- Phase 1 rolling 24-hour IAM and S3 finding counters with configurable policy escalation.
- IAM and S3 exposure detectors that write Markdown reports.
- Phase 2 weighted per-resource risk scores with signal explanations and time decay.
- Offline tests for report parsing, deduplication, escalation, scoring bands, and decay.

## Current Priorities

- Replace phrase-based Markdown parsing with a versioned finding schema.
- Add offline report replay and comparison without changing live state.
- Calibrate weights using reviewed examples and add optional asset criticality/ownership context.
- Add detector coverage for CloudTrail or GuardDuty after the finding schema is stable.

## Future Work

- Connect policy to responders only through dry-run, explicit approval, idempotency, and an audit log.
- Add multi-account inventory and durable state storage.
- Evaluate scoring quality against labeled findings before treating score bands as operational policy.

## Known Boundaries

- The core ingests detector Markdown reports and does not call AWS.
- Risk scores produce recommendations only; they do not trigger remediation.
- Responders are standalone scripts and must be reviewed before use against a live account.
